Overview & Architecture

Ownbase transforms any standard Windows 10 or Windows 11 computer into a self-hosted cloud server platform. Unlike traditional server orchestration platforms that rely on Linux virtualization (WSL2, Docker Desktop, Hyper-V), Ownbase operates directly on bare-metal Windows using native Win32 executables.

Key Architectural Advantage: By bypassing virtualization, Ownbase consumes under 150 MB of base RAM, boots in under 2 seconds, and accesses Windows storage drives directly without filesystem translation penalties.

Core Subsystems

  • Edge Ingress: Caddy v2.8 reverse proxy handling HTTP (:80) and HTTPS (:443) ingress and dynamic domain routing.
  • API Gateway: Express/Node REST daemon listening strictly on loopback (:3001) for security isolation.
  • Database Engine: Portable PostgreSQL 16 initialized on loopback (:5432) with SCRAM-SHA-256 and Prisma ORM.
  • Mesh Overlay: Tailscale WireGuard integration for zero-config remote access across cellular and external networks.
  • Storage & Streaming: FileBrowser with HTTP 206 Byte-Range streaming for instant video playback on mobile devices.
  • Photos Hub: Timeline photo gallery, favorites system, and smartphone camera roll sync.

System Requirements

Ownbase is designed to run efficiently on any modern Windows system, from compact mini-PCs to powerful desktop workstations:

  • Operating System: Windows 10 (Build 19041+) or Windows 11 (64-bit).
  • Processor: x64 Dual-Core CPU (Intel Core i3 / AMD Ryzen 3 or higher recommended).
  • Memory: 4 GB RAM minimum (8 GB+ recommended if running local AI models with Ollama).
  • Disk Space: 500 MB free space for core engines; additional space for your personal files and databases.
  • Network: Local Wi-Fi or Ethernet; Tailscale account for remote mobile access.

Installation Options

Ownbase provides two packaging formats to accommodate different usage workflows:

1. Windows Setup Installer (NSIS)

The recommended setup for a dedicated home or office server. The installer creates a managed Windows Service (NT SERVICE\Ownbase), configures Windows Firewall automatically, creates desktop and start menu shortcuts, and sets up background delayed autostart.

Installed Path Structure 
%LocalAppData%\Programs\ownbase\     # Binaries and desktop shell
%ProgramData%\Ownbase\              # PostgreSQL data, secrets, and runtimes

2. Standalone Portable Executable

A single executable that runs immediately without administrative privileges or registry writes. All configuration, databases, and logs are kept isolated in a ./data/ directory adjacent to the executable.

Portable Path Structure 
Ownbase-Portable-v0.1.0.exe
└── data\                           # 100% self-contained data directory

Tailscale VPN Remote & Mobile Access

With Tailscale integration, you can securely access your Ownbase server from your iPhone, Android phone, or another laptop from anywhere in the world without configuring port forwarding on your home router or exposing ports to the public internet.

Important Windows Rule: Windows Defender Firewall treats the virtual Tailscale network adapter as a Public network by default. If your firewall rule only allows Private networks, Tailscale traffic will be silently dropped!

Step-by-Step Setup

  1. Install Tailscale on PC: Download and install Tailscale for Windows, sign in with your account, and verify your assigned 100.x.y.z IPv4 address.
  2. Install Tailscale on Mobile: Download the Tailscale app on your phone (App Store or Google Play) and sign in using the same account.
  3. Apply Windows Firewall Rule: Open an elevated PowerShell session (Run as Administrator) and execute:
PowerShell (Run as Administrator) 
New-NetFirewallRule -Name "Ownbase-Tailscale-Inbound" `
    -DisplayName "Ownbase Tailscale Remote Access" `
    -Description "Allows inbound web traffic from Tailscale WireGuard mesh devices (100.64.0.0/10)" `
    -Direction Inbound `
    -Protocol TCP `
    -LocalPort 80, 443, 3000, 3001, 8080 `
    -RemoteAddress 100.64.0.0/10 `
    -Action Allow `
    -Profile Any

Accessing from Mobile Browser

Make sure Tailscale is Connected (active VPN indicator) on your phone. Then open your mobile browser (Safari, Chrome, Firefox) and navigate directly to:

Mobile Browser URL 
http://<your-pc-tailscale-ip>/    # Example: http://100.85.12.34/

Windows Firewall Rules

Ownbase relies on Caddy as its sole external ingress gateway on ports 80 (HTTP) and 443 (HTTPS). All internal microservices (Postgres, daemon, terminal) bind strictly to loopback (127.0.0.1) for security hardening.

Port Protocol Purpose Allowed Scope
80 TCP Caddy HTTP Web Dashboard & Reverse Proxy LAN & Tailscale (Profile: Any)
443 TCP Caddy HTTPS TLS Reverse Proxy LAN & Tailscale (Profile: Any)
3001 TCP Ownbase Internal REST API Daemon Loopback only (127.0.0.1)
5432 TCP PostgreSQL 16 Relational Database Engine Loopback only (127.0.0.1)
8080 TCP Native FileBrowser Storage Engine Loopback (Proxied via files.*)

Caddy Ingress & Routing

Ownbase integrates the official Caddy reverse proxy engine. When new services or custom subdomains are created, Ownbase programmatically commits dynamic routing rules via Caddy's Admin REST API (port 2019):

  • hub.<IP>.nip.io or http://<IP>/ → Main Hub Dashboard & REST Gateway
  • files.<IP>.nip.io → FileBrowser cloud storage with media streaming
  • photos.<IP>.nip.io → Photos Hub & mobile camera roll backup
  • ai.<IP>.nip.io → Ollama LLM inference engine
  • s3.<IP>.nip.io → MinIO Amazon S3-compatible bucket storage

PostgreSQL 16 Cluster

Ownbase includes an embedded portable PostgreSQL 16 engine. Upon first launch, Ownbase automatically:

  1. Initializes a localized database cluster using initdb.exe with UTF-8 encoding.
  2. Configures postgresql.conf to bind strictly to 127.0.0.1.
  3. Generates a secure 256-bit password stored in encrypted secrets and enforces scram-sha-256 authentication.
  4. Executes automated Prisma schema migrations (prisma migrate deploy).

HTTP 206 Byte-Range Media Streaming

Playing multi-gigabyte 4K or 1080p video files (MKV, MP4, WebM) on mobile devices often causes buffering or fails if the server attempts to download the entire file first.

Ownbase implements a native HTTP 206 (Partial Content) byte-range engine:

HTTP Request Header Example 
GET /api/v1/files/stream?path=Movies/4k_nature.mp4
Range: bytes=1048576-2097151

HTTP/1.1 206 Partial Content
Content-Range: bytes 1048576-2097151/4294967296
Content-Length: 1048576
Content-Type: video/mp4

This allows mobile browsers to seek forward instantaneously to any timestamp in a 20 GB video file with zero lag.

Google Photos & Memories Service

Ownbase includes a dedicated Photos Hub designed to deliver a private, self-hosted alternative to Google Photos:

  • Chronological Timeline: Automatically groups media into sections ("Today", "Yesterday", "October 2026").
  • 1-Tap Mobile Uploads: Seamlessly upload photos and videos directly from iOS and Android camera rolls.
  • Interactive Lightbox: Full-screen high-resolution preview with zoom, swipe, and favorite starring.
  • Metadata Extraction: Automatically reads EXIF orientation and capture dates.

Native Process Supervisor

The Process Supervisor monitors background executables on bare-metal Windows:

  • Job Objects Isolation: Groups child processes to enforce RAM/CPU quotas and prevent rogue memory leaks.
  • Auto-Restart Recovery: Automatically restarts crashed services using exponential backoff.
  • Tree Termination: Eliminates zombie processes on shutdown using recursive Win32 termination (taskkill /PID <PID> /T /F).
  • Live Console Logs: Streams real-time stdout and stderr from managed executables directly to the UI.

REST API & OpenAPI Spec

Every feature in Ownbase is accessible via a standardized REST API. The machine-readable OpenAPI 3.0 specification is available at:

OpenAPI 3.0 Endpoint 
GET http://127.0.0.1:3001/api/openapi.json

Core Endpoints Summary

Method Endpoint Auth Description
GET /api/v1/system/about Public Application version, developer contact, runtime engines, and system metadata
GET /api/v1/health Public Probes PostgreSQL and daemon cluster health
GET /api/v1/system-info User Hardware telemetry (RAM, CPU, LAN, and Tailscale IPs)
GET /api/v1/files/stream User High-performance HTTP 206 byte-range media stream
POST /api/v1/files/upload User Multi-file chunked upload engine
GET /api/v1/photos/timeline User Chronological photo and video timeline metadata

Building from Source

Clone the repository and build packages using Node.js v18+ on Windows:

Terminal / PowerShell 
# 1. Clone repository
git clone https://github.com/rhmunna143/ownbase.git
cd ownbase

# 2. Install dependencies
npm install

# 3. Build Next.js Dashboard static export
npm run build:next

# 4. Compile Electron TypeScript
npm run build:electron

# 5. Build distribution packages (.exe)
npm run dist:all

Generated executables will be placed in the release/ folder:

  • release/Ownbase-Setup-v0.1.0.exe (NSIS Installer)
  • release/Ownbase-Portable-v0.1.0.exe (Portable Executable)

Troubleshooting & FAQ

1. Mobile Tailscale Connection Timed Out

Symptoms: The dashboard opens on your PC at http://localhost/, but fails to connect on your phone via Tailscale.

Fix: Windows Firewall classifies the Tailscale network adapter as a Public profile. Execute the PowerShell firewall command with -Profile Any:

PowerShell (Admin) 
New-NetFirewallRule -Name "Ownbase-Tailscale-Inbound" `
    -DisplayName "Ownbase Tailscale Remote Access" `
    -Direction Inbound -Protocol TCP -LocalPort 80,443,3000,3001,8080 `
    -RemoteAddress 100.64.0.0/10 -Action Allow -Profile Any

2. Portable Version: "C:AppData/.../index.html, js not found"

Cause: In older packaging configurations, Next.js static files were loaded via Chromium's file:// protocol. Because Next.js outputs script tags with absolute paths (/_next/...), Chromium tried to find scripts at C:\_next\....

Fix: Ownbase routes all dashboard views through its built-in HTTP server (http://127.0.0.1:3001). This completely eliminates drive root resolution issues across both portable and installed modes.

3. Port 80 Already in Use

Cause: Windows World Wide Web Publishing Service (IIS), Skype, or another server is bound to port 80.

Fix: Stop IIS by running net stop w3svc in an elevated command prompt, or change IIS's binding.
